## 進め方

1. 島データを読み、位置の記述（「中央やや北寄り」「北西麓」「時計回り」「徒歩約5分」など）と数値（東西6.8km・南北4.2km、面積19.6km²、周囲21km、標高428m）を座標の条件に置き換えた。
2. `src/geo.py` で海岸線・周回道路・停留所・スポット・登山道を km 単位で作り、`validate()` でデータとの一致（寸法、面積、時計回り、停留所の順番、方角、最寄りバス停、徒歩時間と距離）を自動で確かめた。
3. `src/terrain.py` で、あおい岳を最高点（ちょうど428m）とする標高モデルを作り、段彩と陰影の画像、等高線にした。
4. `src/render_map.py` で地図の SVG を組み立てた。ラベル同士の重なりを自動で判定し、0件になるまで位置を調整した。
5. Web版（`index.html`）、1枚もののSVG（地図＋ガイド欄）、印刷用A3（2ページ）を同じデータから生成した。
6. Chrome で撮影したスクリーンショットを見ながら、見た目と読みやすさを繰り返し直した。

## つまずいた点

- **周囲21km・道路21kmとの整合**：なめらかな楕円では周囲が約17.5kmにしかならない。入り江と岬を足し、海岸に細かなゆらぎを加えて、海岸線を21.0km、面積を19.7kmにした。外接寸法は 6.80×4.20km に正規化した。道路は海岸に沿わせても約19.2kmが限度で、それ以上の蛇行は不自然になるため、README に差分を明記した。
- **陰影の向きの取り違え**：勾配の符号を誤って、光が南西から当たる陰影になっていた。北西からの光に直した。
- **距離変換の扇状の筋**：海岸からの距離をそのまま使うと、陰影に放射状の筋が出た。距離の場をぼかして解消した。
- **静浦湾が湾に見えない**：最初の形は斜めの海岸線にしか見えなかった。西の岬を張り出させて入り江にした。
- **路線図**：10列の横一列にすると停留所名が折り返して読みにくかった。島の形（上＝北海岸、下＝南海岸）に合わせて停留所を並べた周回ループ型に作り直した。
- **印刷版の裏面のはみ出し**：要素を計測しながら、情報を削らずに詰めた。
- **スマホの路線図**：CSS の子孫セレクタが内側の li にも効き、文字が1字ずつ縦に並んでいた。子セレクタに直した。
- **自動テストのタイミング**：アニメーションの途中で判定して失敗することがあった。表示範囲の変化が止まるのを待つ形にして安定させた。

## 自己申告の工夫

- 地名・数値・説明文を1か所（`src/aoi_data.py`）から差し込み、位置関係は自動チェックで担保した。データにない施設名は書かず、飾りは名前のない描画だけにした。
- 周回線は、道路上の向きの矢印、停留所の順番の数字、「起点」の札、島の形に合わせたループ型の路線図で、「あおい港から時計回り」が地図でも図でも同じ形で伝わるようにした。
- 東の朝日岬と西の夕凪岬にちなみ、海の色を東は朝焼け、西は夕焼けの色に寄せ、タイトルを縦書きにした。
- 時間に縛られるスポット（朝市は7:00〜9:00ごろ、朝日岬は早朝、夕凪岬は夕方）と、帰りの最終便（島発18:20）を、地図・ガイド・モデルコースのそれぞれに書き添えた。
- Web版では、地図の拡大・移動、スポットの詳細、絞り込み、モデルコースの経路表示ができる。キーボード操作、スマホ表示、動きを減らす設定にも対応した。
- SVG は1ファイルで完結する（フォントのサブセットと地形画像を埋め込み、foreignObject は使っていない）。整形式の XML であることと、librsvg でも描けることを確認した。
