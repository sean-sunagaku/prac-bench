# ラウンド1提案：Gemini 4 Carbon

## 案1：単一HTMLで作る「軽トラ限界引っ越し」2D物理ゲーム
### 狙い
2D物理挙動の設計力、Canvas/SVGによる具体的なオブジェクト描画力、そして「触って気持ちいい手触り（ゲームフィール・効果音・演出）」の総合センスを比較する。単なる動くプログラムにとどまらず、荷物の重心バランスやサスペンションの挙動、荷崩れ時のハプニング演出といった「遊びの面白さ」をどこまで自律的に作り込めるかでモデルの個性が鮮明に分かれる。実装やパラメータ調整が甘いモデルでは発進直後に軽トラや家具が吹き飛ぶなど、失敗すら視覚的なエンターテインメントとして楽しめる点も狙いである。

### 具体的なタスク内容
- **題材**：引っ越し荷物を軽トラックの荷台にパズルのように積み込み、段差だらけの悪路を走破してゴールへ届ける1画面完結の2D物理バランスゲーム。
- **素材**：外部画像・外部音声ファイルの読み込みは全面禁止（リンク切れと著作権リスクを排除）。グラフィックはHTML5 CanvasまたはSVGによるコード描画、効果音はWeb Audio APIによるプロシージャル合成のみで実装する。物理演算は自作、または `matter-js`（CDN `0.19.0` 固定）の利用のみ許可する。
- **必須要素**：
  1. **積み込みフェーズ**：画面のストック領域から、形状・重量・査定額・特性が異なる7個の荷物（①大型冷蔵庫：重く高単価、②L字ソファ：凹凸形状、③段ボール箱×2：標準、④観葉植物：縦長で倒れやすい、⑤バランスボール：よく弾む、⑥金魚鉢：一定以上の衝撃で割れる最高単価品）を、マウスドラッグとホイール（または `R` キー）回転で軽トラの荷台に積むUI。
  2. **走行フェーズ**：「出発！」ボタンを押すと物理演算が進行し、バネ付きサスペンションを備えた軽トラが自動で右方向へ約15秒間走行する。コースには「急な上り坂」「3連スピードバンプ（段差）」「ゴール手前の急減速ゾーン」の3つの難所を必ず配置する。
  3. **破損・落下判定と精算**：荷台から地面へ落ちた荷物はロスト、金魚鉢は衝撃過多でも破損と判定する。ゴール停止時に残った荷物の明細・合計査定額・評価ランク（S〜D）を表示し、1クリックで初期状態から再挑戦できるリトライボタンを設ける。
  4. **サウンド演出**：ユーザー初回クリック時にAudioContextを初期化し、エンジン音、荷物の衝突音、金魚鉢の破損音、ゴール時の精算演出音を鳴らす。
- **完成条件**：ブラウザで `index.html` を開いた瞬間、タイトル画面を挟まず即座に積み込みフェーズが始まり、コンソールエラーなく走行・精算・リトライまで1周プレイできること。

### 成果物の形式
- 単一ファイル `index.html`（CSS・JavaScriptインライン同梱、1ファイル完結）。
- **5モデルの横並び比較方法**：
  1. **プレイ比較**：運営側で上部切り替えタブと `16:9`（基準 `1280×720`）の `iframe` を備えた比較用ラッパーページを用意し、5モデルの作品を同じ画面サイズ・同じ操作条件で即座に切り替えプレイできるようにする。
  2. **映像比較**：各モデルで「全7個の荷物を積んで『出発！』を押してからゴールするまでの15秒間」をキャプチャし、`5分割（上段3・下段2）の同時再生MP4動画` として1画面に並べる。

- **途中質問・追加指示・再試行の扱い**：途中質問・追加指示は一切禁止（「仕様にない細部はゲームとして最も面白くなるよう自律判断せよ」と共通システム指示で統一）。起動時に画面が真っ白で操作不能な場合のみ、コンソールエラー全文を渡す救済リトライを1回だけ認め、「一発完走／1回修正完走」の区別を記録する。

### この案の弱点
- 物理演算の摩擦係数やバネ定数はわずかな数値差で挙動が激変するため、エージェント実行環境でヘッドレスブラウザによる動作確認ができるかどうかが完走率に影響する。また、コース形状に乱数を使う実装をモデルが選んだ場合、複数回プレイ時の再現性に小さなばらつきが生じる懸念がある。

## 案2：箱庭3Dモデル生成「カピバラの雪見露天風呂」
### 狙い
コード経由での3D空間座標の把握力、有機物（動物）と人工物（岩風呂・竹垣・灯籠）のプロポーション造形力、およびPBRマテリアル（透過・粗さ・自己発光）の設計センスを比較する。「カピバラが湯船に肩まで浸かり、頭の上に柚子がぴったり乗っている」といったパーツ間の接地関係は少しでも座標や回転軸を誤ると浮遊・めり込み・横倒しが起きるため、空間推論の精度が残酷なほど可視化される。さらに自らレンダリング画像を確認して位置ズレを直すマルチモーダル自己修正ループの粘り強さも観察できる。

### 具体的なタスク内容
- **題材**：`幅2.0m × 奥行2.0m × 高さ2.0m` の空間に収まるミニチュア箱庭ジオラマ「カピバラの雪見露天風呂」の3Dモデル（`.glb`）制作。
- **素材**：外部3Dアセットや外部テクスチャ画像の読み込みは禁止。すべてPythonスクリプトまたはBlenderヘッドレススクリプトによるプロシージャル生成（プリミティブ変形、サブディビジョン、ブーリアン、押し出し、頂点カラー、PBRマテリアル設定）のみで構築する。
- **必須要素（計6点）**：
  1. **ジオラマ台座**：2m四方以内の厚みのある土台（雪の積もった地面・岩場のベース）。
  2. **石組みの露天風呂と半透明のお湯**：自然石に囲まれた湯船と、半透明（Alpha BlendまたはTransmission）で表現されたお湯の水面。
  3. **入浴中のカピバラと頭の柚子**：お湯に肩まで浸かり顔が出ているカピバラ1頭（耳・目・鼻先が判別できる造形）と、**その頭頂部に接地して乗っている黄色い柚子1個**。
  4. **竹の湯口と木製の湯桶**：湯船の縁に配置された竹の湯口と、傍らに置かれた湯桶。
  5. **竹垣と積雪**：ジオラマの背面〜側面を囲う和風の竹垣と、岩や垣根の上に積もった雪の塊。
  6. **発光する石灯籠**：火袋部分が暖色系（オレンジ〜電球色）のEmissive（自己発光）マテリアルで光っている石灯籠1基。
- **制約・完成条件**：glTF 2.0バイナリ形式（`scene.glb`）単一ファイルで出力すること。座標系はglTF標準の **Y-up（+Yが上、+Zが正面）**、台座底面の中央を原点 `(0, 0, 0)` とし、総ポリゴン数は10万三角面以下、ファイルサイズは20MB以下に収めること。

### 成果物の形式
- 3Dモデルファイル `scene.glb`（および生成に使用した `.py` スクリプト）。
- **5モデルの横並び比較方法**：
  - 運営側で `<model-viewer>`（またはThree.js）による共通比較ステージHTMLを用意し、**全モデル完全に同一のHDRI環境光・同一のカメラ距離と仰角（斜め上30度）・同一の2m基準グリッド上**に5つの `scene.glb` を並べて同期回転させる。ライティングやカメラワークのごまかしを一切排除し、純粋な造形力と座標精度を同じ尺度で並べる。

### やらせ方
- **初回に渡すプロンプト文案**：
  ```text
  プロシージャル（コード生成）のみで、ミニチュア箱庭3Dモデル「カピバラの雪見露天風呂」を作成し、カレントディレクトリに `scene.glb` として出力してください。

  【必須オブジェクト】
  1. ジオラマ台座（雪の地面と岩場）
  2. 石組みの露天風呂と、半透明マテリアルで表現されたお湯の水面
  3. お湯に肩まで浸かっているカピバラ1頭（耳・目・鼻が分かる造形）と、その頭の上にぴったり乗った黄色い柚子1個
  4. 竹の湯口と、木製の湯桶
  5. 背面〜側面の竹垣と、岩や竹垣の上に積もった雪
  6. 火袋が暖色に自己発光（Emissive）している石灯籠1基

  【規格・制約】
  - 外部3Dデータや外部画像ファイルの読み込みは禁止です。Python（trimesh / numpy / scipy 等）または Blender ヘッドレス実行（`blender -b -P ...`）を用いてスクリプトから生成してください。
  - glTF標準の Y-up（+Yが上、+Zが正面）とし、台座底面の中央を原点 (0,0,0)、全体の外寸を 幅2.0m × 奥行2.0m × 高さ2.0m 以内に収めてください。
  - 総ポリゴン数は10万三角面以下、ファイルサイズは20MB以下とします。
  - 出力後、可能であれば自身で正面・側面・斜め上からプレビュー画像をレンダリングして視覚確認し、パーツの浮遊・めり込み・向きの反転がないか検証してから完了としてください。
  ```
- **共通条件・制限時間・利用可能ツール**：制限時間25分。全モデル共通で Blender 4.x CLI と Python 3.11+（`trimesh`, `numpy`, `scipy`, `pillow` 導入済み）が使えるローカル/コンテナ環境を用意し、レンダリングしたPNG画像をモデル自身が読み取って確認できるマルチモーダルツールを許可する（環境のBlender有無は事前統一：要確認）。
- **「一文プロンプトだけ渡す」方式との相性**：**良い（○）**。『頭に柚子を乗せたカピバラが入浴している雪見露天風呂のミニチュア3DモデルをY-up・2m四方の `scene.glb` で生成して』の一文でも十分成立し、造形の密度差が素直に出る。
- **途中質問・追加指示・再試行の扱い**：途中質問・追加指示は禁止。納品された `scene.glb` がフォーマット破損でロード不能な場合のみ1回だけエラー内容を伝えて再出力を認める。

### 比較・スコアの付け方
- **直感的な見せ方**：5つの箱庭が横並びで同時に1回転する12秒のターンテーブル動画と、斜め上からの静止画比較一覧。
- **評価軸と配点案（100点満点）**：
  - 空間整合性・接地精度（30点）：カピバラがお湯に適切な深さで浸かり、頭に柚子が接地し、灯籠や桶が空中に浮いたり横倒しになったりしていないか。
  - 造形ディテールと認識性（30点）：説明なしで見て「カピバラ」「露天風呂」「竹垣」「石灯籠」と一目で判別できるプロポーションと作り込みか。
  - マテリアル・色彩設計（20点）：お湯の透け感、雪のマットな白さ、濡れた岩の質感、石灯籠の暖色発光（Emissive）が効果的に設定されているか。
  - 箱庭としての構図・情緒（20点）：手前を開けて奥に竹垣と灯籠を配する視線誘導や、冬の温泉らしい情緒があるか。
- **自動測定できる客観指標**：`gltf-validator` によるスキーマエラー件数、バウンディングボックスの範囲逸脱有無（`[-1,1]×[0,2]×[-1,1]` 収束）、透過/Emissiveプロパティの使用有無、メッシュ数および総三角面数。
- **モデルの個性が見えるポイント**：「球と円柱を並べただけの記号的な雪だるま風になるモデル」と、「ノイズ変形で自然石の凹凸を作りカピバラの丸みまで造形するモデル」、さらに「プレビュー確認で『柚子が宙に浮いている』と気づいて座標を修正するモデル」の差が一目瞭然になる。
